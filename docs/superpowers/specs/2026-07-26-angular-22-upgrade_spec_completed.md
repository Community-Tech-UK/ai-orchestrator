# Angular 22 Upgrade Specification

**Status:** Completed and independently verified

**Implementation plan:** [2026-07-26-angular-22-upgrade_plan_completed.md](../plans/2026-07-26-angular-22-upgrade_plan_completed.md)

## Goal

Upgrade every maintained Angular application in this repository from Angular 21 to the latest compatible Angular 22 patch release while preserving existing renderer and mobile behavior.

## Scope

- Upgrade the root Electron renderer's Angular framework, CLI, build tooling, CDK, lint tooling, `ngx-echarts`, and TypeScript compatibility floor.
- Upgrade the independently locked Capacitor application under `apps/mobile/`.
- Run Angular's official 21-to-22 migrations for each Angular workspace.
- Update current-version references in active project documentation and source comments.
- Do not rewrite historical completed specs or unrelated documentation that accurately records the version used at that time.
- Do not alter pre-existing unrelated working-tree changes.

## Compatibility Requirements

- Angular packages must resolve to the latest mutually compatible Angular 22 patch releases.
- TypeScript must resolve within Angular 22's supported `>=6.0.0 <6.1.0` range.
- Development Node versions must satisfy Angular 22: `^22.22.3`, `^24.15.0`, or `^26.0.0`.
- RxJS must remain in Angular 22's supported `^6.5.3 || ^7.4.0` range.
- The renderer must remain zoneless in application runtime.
- Root and mobile lockfiles must be regenerated by npm, not hand-edited.

## Migration Design

Use a controlled hybrid migration:

1. Run the official Angular CLI update schematics separately in the root and mobile workspaces.
2. Review all generated changes so migrations cannot silently overwrite unrelated dirty work.
3. Align Angular-adjacent packages to releases whose peer ranges support Angular 22.
4. Resolve TypeScript 6 or Angular 22 compatibility errors with the smallest local edits.
5. Verify package resolution, compilation, lint, production builds, and tests.

This is a framework dependency/configuration migration rather than a new behavior. Existing regression checks and production builds are the acceptance tests; no artificial behavior test will be added solely to force a red phase.

## Acceptance Criteria

1. Root `package.json` and `package-lock.json` resolve Angular 22 and TypeScript 6.0-compatible versions without invalid peers.
2. `apps/mobile/package.json` and its lockfile resolve Angular 22 and TypeScript 6.0-compatible versions without invalid peers.
3. Official Angular 21-to-22 migrations have run in both workspaces and their edits have been reviewed.
4. Root renderer typecheck, lint, production build, maximum TypeScript LOC check, and full quiet test suite pass, except that any proven pre-existing failure is reported separately and not attributed to this upgrade.
5. Mobile typecheck and production build pass.
6. Active repository documentation identifies the renderer as Angular 22.
7. A fresh completion-gate agent returns `VERDICT: PASS` with no actionable findings.

## Baseline Evidence

Before the upgrade:

- Root production renderer build: pass, with the existing initial-bundle budget warning.
- Root application typecheck: pass.
- Root Angular lint: pass.
- Root spec typecheck: one pre-existing failure because `src/shared/validation/local-ai-guard.schemas.spec.ts` imports a missing untracked implementation file.
- Mobile typecheck: pass.
- Mobile production build: pass.

## As-Built Outcome

- Root Angular framework and CLI packages resolve to 22.0.8; CDK resolves to 22.0.6.
- The mobile Angular framework, CLI, and build package resolve to 22.0.8.
- Both workspaces use TypeScript 6.0.3.
- Root lint tooling resolves `angular-eslint` 22.1.0 and `typescript-eslint` 8.65.0; `ngx-echarts` resolves 22.0.0.
- Angular's official migrations applied safe-navigation preservation wrappers and scoped extended-diagnostic suppressions.
- The root retains `@angular-devkit/build-angular` 22.0.8 because switching to the optional direct `@angular/build` package would require Vitest 4 and caused 181 existing spec type errors. The mobile workspace already uses `@angular/build` 22.0.8.
- The npm lock refresh initially moved application Zod to 4.4.2 and broke two loop-schema defaulting tests. Zod is now pinned to the previously working 4.3.6; the targeted suite and complete suite pass.
- Root production audit reports zero vulnerabilities. The mobile app's ignored local lock retains one pre-existing moderate DOMPurify advisory from an unchanged manifest entry.
- The second fresh completion reviewer returned `VERDICT: PASS` with no actionable findings after an isolated full-suite run passed 1,590 files and 15,862 tests with zero failures and one unrelated platform-conditional skip.
