# Research savings claims

Source: October 10 and October 20 research lists (`claude_oct-todo.md`, “Previously rejected” and “Considered and rejected”; `claude_oct-2-todo.md`, AppendixC). These are recorded stances, not new measurements. Reopening needs the condition below, not another unscoped sweep.

## File rereads as a major savings lever

- Stance: Rejected at present.
- Reason: Only 7.3% of reads repeated a range already in context, about 0.8% of spend in the October sample.
- Reopen when: Deduplicated new measurements show material avoidable cost.

## One-hour helper cache

- Stance: Rejected as a saving.
- Reason: It remained cost-neutral and long-gap rewrites still fell eleven times.
- Reopen when: Observed read/write/output mix under current prices shows a net gain.

## Maximum effort as a savings lever

- Stance: Rejected.
- Reason: Measured max-effort helper requests were no longer or dearer than high-effort requests.
- Reopen when: A controlled like-for-like comparison shows meaningful savings beyond ±3% noise.

## One-shot cache markers

- Stance: Rejected as applicable here.
- Reason: Harness helper calls set none, so the proposed removal has no target.
- Reopen when: The real helper request path starts adding such markers.

## Seven claw-code runtime fixes

- Stance: Rejected as implementation evidence.
- Reason: Upstream reverted all seven the same day; a transient log is not current behavior.
- Reopen when: Current upstream source reintroduces and validates a relevant fix.
