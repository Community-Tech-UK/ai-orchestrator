# Defect identifier reservations

Before filing a new reproduced live-test defect, run:

```sh
node scripts/next-lt-id.mjs --reserve
```

Run from the root checkout or an AIO-managed linked worktree. An older worktree can invoke the root script by absolute path. Git's common directory identifies the authoritative root checkout. The allocator reads every ID table in its `## Remediation Index` section, including root changes not yet committed. It also reads durable claims in `<common-git-directory>/aio-lt-reservations` and exclusively creates the next claim. The printed identifier belongs to this defect; retain it with the evidence and use it for the register row, details and links.

Claims are immutable. Their filenames are the allocation record, including an empty file from an interrupted writer. The allocator flushes the claim and directory before printing. Competing callers retry exclusive creation for at most five seconds. There is no persistent PID lock to expire, steal or clear. A failed or interrupted invocation can leave a gap, which is intentional: never delete claims or reuse their numbers. Malformed entries, symlinked storage and filesystem failures stop allocation with an error. Preserve the ledger and inspect the reported problem before retrying. Restore this ledger together with the common Git directory after a recovery; never recreate it from an old branch snapshot.

An explicit register path with `--reserve` must resolve to the authoritative root register. Without `--reserve`, the existing optional-path command remains read-only: it reports the next index number, ignores reservation claims, and supplies no ownership. Do not use that output for new defects. Historical documents telling a worker to recheck a non-reserving number are superseded by this rule.

Independent remote clones do not share the coordinator's Git directory. For a remote Plan Queue job, overwrite the turn's report file with exactly `{"item_id":"the assigned item ID","reserve_defect_ids":2}` (use the actual item ID and a count from 1 to 8), then end the turn. The coordinator reads this through the existing authenticated job channel, executes the authoritative root allocator, and sends the reserved identifiers to the same worker as its next message. This is permitted once per remote report turn and is not a completion report. Continue work after the response, then overwrite the request with the usual completion report. A repeated or malformed request, or allocation failure, parks the job without completing it. Retain additional unnumbered evidence in `follow_ups`. A coordinator crash may leave unused claims; they remain reserved and cannot collide. Restart recovery closes the old remote session, collects its work and prepares a new turn/report file instead of replaying the old request. The pending response uses the queue's ordinary persisted worker instruction; if it was never delivered, leave the numbers unused. Other independently launched remote agents must ask their coordinator owner to run the command and return the identifiers; they do not have this queue-report channel. Never mint a parallel ledger on another computer. This command does not register a defect, edit histories, reconcile existing collisions, change any branch or merge work.
