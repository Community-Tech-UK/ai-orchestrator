## Design decisions and regression risks

- `autonomous` remains the existing expiring unattended option; `persistent` is distinct and means until revoked, including future agent sessions.
- Existing broad grants must not accidentally bypass challenge or secret-handling checks. Permanent approval cannot become a global cross-computer or cross-site grant.
- `unknown` retains exact-action approval. Payment and identity-sensitive requests retain their existing review/broker boundaries.
- Rebuild the grants table through an additive migration because its mode CHECK constraint excludes `persistent`; preserve existing rows and indexes. Persist explicit operator credential consent separately so legacy/campaign grants do not acquire new authority.
- Permanent authorization uses the exact approval origin (including a nondefault port), even when a proposed grant contains wildcard or multiple origins. Without a usable HTTP(S) origin, the UI omits forever and the builder rejects it.
- Authorization lookup supplements the recent-grants list with active persistent grants for the exact origin and computer/profile, so more than 100 newer grants cannot hide standing consent. The regular list remains bounded.
- Agent grant requests cannot create persistent grants; agents cannot revoke the operator's shared persistent grants. Operator revocation remains available on the Permissions page.
